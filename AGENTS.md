# DentalFlow — Frontend Instructions

---

# 🧠 Product Context

DentalFlow is a SaaS platform for dentists focused on:

- increasing revenue
- improving digital presence
- generating patient acquisition
- delivering measurable growth

The frontend must always reflect:

- premium
- clean
- modern
- trustworthy
- business-oriented

---

# 🏗️ Frontend Responsibility

The frontend is responsible for:

- UI/UX
- User experience
- State management
- API consumption
- Visual consistency
- User interactions

❗ The frontend must NOT contain business logic or payment logic.

---

# ⚙️ Frontend Stack (DO NOT CHANGE)

- React
- Vite
- TypeScript
- Tailwind CSS
- shadcn/ui

---

# 🚫 Execution Rules

Before implementing:

1. Analyze existing components
2. Check for reusable UI patterns
3. Avoid duplication
4. Follow current design system
5. Create planning
6. Ask for approval

---

# 💻 Terminal Rule

Never execute commands.

Always:
- provide command
- wait for user

---

# 🧩 Code Standards

- Reusable components first
- Avoid page-specific components
- Keep components small
- Strong typing
- Clean structure

---

# 🔍 Analysis Rules

Always check:

- existing component?
- reusable?
- duplication risk?
- matches pattern?

---

# 🎨 UI / UX Guidelines

- Clean
- Minimal
- Professional
- Clear hierarchy
- Consistent spacing

---

# 🎨 Design System

## Primary
#1E3A8A

---

# 🔌 API Integration Rules

- All API calls must be centralized in services
- Never call API directly inside components
- Use proper typing for responses
- Prepare for future React Query usage

---

# 🔒 Security (Frontend)

- Never expose sensitive data
- Never trust client-side validation alone

---

# 🧠 Response Format

1. Analysis
2. Reuse
3. Risks
4. Planning
5. Approval
