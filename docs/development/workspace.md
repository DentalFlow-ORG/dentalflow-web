# Working with both repositories

Keep sibling checkouts `dentalflow-web/` and `dentalflow-api/`. Read each repository's AGENTS.md before editing; do not duplicate backend business rules in frontend code. No machine-specific path is required.

## Setup

Use Bun 1.3.9 as pinned and Node 24 (API engines require >=24.15.0 <25). Dependencies are installed separately in each checkout. These are developer setup instructions; an agent must obtain approval before installing dependencies under the frontend policy.

```sh
# Terminal 1: dentalflow-api
bun install --frozen-lockfile
cp .env.example .env
# Edit .env with your own local database and integration configuration.
bunx prisma generate
# Confirm BOTH DATABASE_URL and DIRECT_URL target your intended local DB first.
bunx prisma migrate deploy
bun run start:dev

# Terminal 2: dentalflow-web
bun install --frozen-lockfile
cp .env.example .env
bun run dev
```

PowerShell equivalent for copying: `Copy-Item .env.example .env` (only when `.env` does not already exist). Never overwrite an existing local environment. API default: `http://localhost:3000/api`; SPA default: `http://localhost:5173`. Use localhost consistently; mixing 127.0.0.1 and localhost changes cookie/site behavior. The frontend requires VITE_API_URL including `/api`, without a trailing slash. It does not discover the API automatically and has no Vite proxy contract.

Use a dedicated local PostgreSQL database for development. The existing test compose file is for **disposable tests**, not a persistent development database. Configure runtime pooled DATABASE_URL and migration DIRECT_URL explicitly. Prisma config reads process env and example/local files; do not assume a CLI command is isolated merely because it is run locally. Existing maintainer `.env` files can target a shared Supabase database. The demo seed now refuses non-development/test environments and non-loopback PostgreSQL URLs before constructing a client. It contains known demonstration credentials and provider-specific Stripe price IDs; never use it for production provisioning.

Account registration creates a clinic owner; plan/trial selection follows. Plans must exist in the database for billing. The seed mixes catalogue and demo accounts, so it is only appropriate on a disposable development database after review. Production catalogue provisioning and initial admin creation require a controlled process; do not blindly reuse the demo seed.

## Authentication and provider tests

Local refresh cookies use HttpOnly/Lax over HTTP; production uses HttpOnly/Secure/None and exact-origin checks. Access tokens stay in memory; a reload uses the refresh cookie. A 402 navigates to subscription selection. Third-party-cookie restrictions cannot be tested in jsdom; use [browser QA](../quality/frontend-browser-qa.md).

Keep AI and WhatsApp real delivery disabled unless intentionally testing them. Google login and Calendar have separate OAuth clients/scopes/callbacks. Configure exact redirect URIs. For Stripe, use test-mode keys and the CLI:

```sh
stripe listen --forward-to http://localhost:3000/api/billing/webhook
```

Use the printed test webhook secret and follow the [backend test-mode checklist](../../../dentalflow-api/AGENTS.md#9-stripe). No card data belongs in DentalFlow. Do not run real payment/provider calls from automated suites. Resend without a key logs the reset link only in development; production boot requires RESEND_API_KEY and MAIL_FROM; runtime delivery failure still preserves the generic request response to prevent enumeration. Verify actual delivery.

## Environment inventory

Do not copy real values into documentation. All VITE variables are public build-time configuration. Changing deployment variables may require rebuilding the SPA. Backend source references are generated by the source inventory; conditional boot requirements are implemented in `src/config/validate-env.ts`.

| Category | Variables | Requirement / behavior |
| --- | --- | --- |
| Frontend | VITE_API_URL | Required for API requests; includes API prefix. Coordinate with Vercel CSP connect-src. |

| Runtime | NODE_ENV, PORT, API_PREFIX | development / 3000 / api defaults. Production changes cookie/security behavior. Keep api prefix until dictation matcher is generalized/tested. |
| CORS / redirects | FRONTEND_ORIGIN, FRONTEND_URL | Exact comma-separated origins and one base URL. Both required HTTPS in production. No wildcard. |
| Database | DATABASE_URL, DIRECT_URL | Runtime connection; Prisma migration connection. DIRECT_URL required by production validator. Secrets. |

## Validation

Frontend: `bun run typecheck`, `bun run test` (or coverage run for the same full suite), `bun run build`, `bun run check`; `bun run knip` and `bun run knip:production` after replacements. API: `bun run verify`; use `lint:check`, because `lint` mutates files.

For real database verification, start Docker and, in the API checkout:

```sh
bun run test:db:up
bun run test:migrations
bun run test:integration
bun run test:e2e
```

The tests use local port 5433. Do not set DATABASE_URL_TEST to a shared/cloud DB or weaken its safety guard. `test:db:down` deletes the disposable volume; run it only when finished with that test data. `db push` is not migration validation.

Regenerate route/database source references from the frontend:

```sh
bun scripts/audit-source-inventory.cjs ../dentalflow-api --write
```

The inventory uses the existing TypeScript compiler; no added package or running service. Review dynamic requests manually. It does not replace OpenAPI or contract tests.

## Common failures

| Symptom | Check |
| --- | --- |
| API connection / CSP error | VITE_API_URL, API process, exact CORS origin, Vercel connect-src; a frontend build alone does not prove connectivity. |
| Login works, reload logs out | Refresh cookie, browser third-party-cookie settings, consistent local hostname, Origin allowlist, HTTPS in production. |
| Subscription remains incomplete | Test/live mode mismatch, webhook forwarding/signature, event error state; use documented reconciliation dry run first. |
| Password request succeeds but no email | Generic response is intentional; check Resend key, sender and delivery logs. |
| Dictation 413 after prefix change | Bootstrap matcher recognizes only api/unprefixed paths. |
| Integration suite cannot connect | Docker engine and disposable port 5433; never substitute development Supabase credentials. |
